## 파트5 (15:15~16:00)
 static import 기능 java5.0부터 나옴
 GoF 패턴의 Singleton Pattern에 대한 설명, 장점, 스프링 컨테이너가 스프링 빈을 생성할 때 왜 이 패턴을 적용하여 객체를 생성하는지 공부
 
 싱글톤 패턴(Singleton Pattern)은 GoF(Gang of Four) 디자인 패턴 중 생성(Creational) 패턴에 속하며, 애플리케이션 전체에서 특정 클래스의 인스턴스가 오직 하나만 생성되도록 보장하고, 어디서든 그 인스턴스에 전역적으로 접근할 수 있게 하는 패턴입니다.
 
 2. 싱글톤 패턴의 장점과 주의할 점
장점
메모리 효율성: 한 번 생성된 객체를 재사용하므로 불필요한 객체 중복 생성을 막고 메모리를 아낄 수 있습니다.

인스턴스 생성 비용 감소: DB 커넥션 풀, 설정 정보 로더, 로거(Logger)처럼 초기화 비용이 큰 객체를 매번 다시 만들지 않아도 됩니다.

공유 자원 및 전역 상태 관리 용이: 애플리케이션 전반에서 공유해야 하는 설정이나 캐시, 서비스 객체 등을 일관된 상태로 접근·관리하기 수월합니다.

주의할 점
상태(State)를 가지면 위험함: 인스턴스 내부에 변경 가능한 상태(필드)를 두면 멀티스레드 환경에서 동시성 이슈(경쟁 조건)가 발생할 수 있습니다. 따라서 싱글톤 객체는 가급적 무상태(Stateless)로 설계해야 합니다.

테스트 및 결합도 문제: 전역 접근이 쉬워질수록 해당 객체에 강하게 결합될 수 있으며, 단위 테스트 시 격리나 목(Mock) 객체 교체가 번거로워질 수 있습니다.

3. 스프링 컨테이너가 스프링 빈을 싱글톤으로 관리하는 이유

대규모 요청 처리와 자원 효율성:
웹 애플리케이션처럼 동시에 수많은 사용자 요청이 들어오는 환경에서, 요청마다 컨트롤러·서비스·리포지토리 객체를 새로 생성하고 버리면 힙 메모리 낭비와 가비지 컬렉션(GC) 부하가 커집니다. 인스턴스를 하나만 만들어 공유하면 성능과 메모리 효율이 크게 높아집니다.

일관된 객체 생명주기와 의존성 주입(DI) 관리:
스프링 컨테이너는 빈의 생성, 의존성 주입, 초기화, 소멸까지 생명주기를 중앙에서 관리합니다. 싱글톤으로 관리하면 애플리케이션 전반에서 동일한 빈 참조를 바탕으로 일관된 의존 관계와 AOP(프록시 적용 등)를 깔끔하게 구성할 수 있습니다.

참고 (GoF 싱글톤 vs. 스프링 싱글톤):

GoF의 전통적인 싱글톤은 클래스 스스로 private 생성자와 static 메서드로 인스턴스 개수를 통제하는 방식이지만, 스프링은 싱글톤 레지스트리(Singleton Registry)라는 컨테이너 메커니즘을 통해 빈을 싱글톤으로 관리합니다. 덕분에 클래스 자체를 싱글톤 코드로 복잡하게 작성하지 않으면서도(일반 POJO 유지), 컨테이너가 단일 인스턴스 보장과 테스트 용이성·유연성을 함께 챙길 수 있습니다.
