## 파트2 (10:30~11:30)

### @Autowired vs @Resource

| 구분 | @Autowired | @Resource |
| --- | --- | --- |
| 출처 | Spring 전용 | Java 표준 (JSR-250, 우리 프로젝트는 `javax.annotation.Resource`) |
| 찾는 기준 | **타입** 먼저 → 여러 개면 `@Qualifier`/`@Primary` → 필드 이름 | **이름(id)** 먼저 → 없으면 타입 |
| 쓸 수 있는 곳 | 생성자, 필드, 세터, 파라미터 | 필드, 세터 (**생성자 X**) |
| 기타 | `required = false`, `List<T>`로 여러 빈 한꺼번에 주입 가능 | 이름을 직관적으로 지정 |

```java
@Autowired                     // 타입으로 찾음 (Hello 빈이 2개 → 필드명 hello와 같은 id 선택)
Hello hello;

@Autowired
@Qualifier("helloCons")        // 같은 타입이 여러 개일 때 id로 좁힘 (단독 사용 X)
Hello hello2;

@Resource(name = "helloCons")  // 처음부터 id로 찾음
Hello hello3;
```

- **언제 뭘 쓰나**
  - 기본은 `@Autowired` (특히 생성자 주입: final로 불변, 테스트 쉬움)
  - 같은 타입 빈이 여러 개이고 **id로 딱 집어야 할 때** → `@Resource(name=...)` 또는 `@Autowired + @Qualifier`
- **주의**: `@Resource(name="...")`, `@Qualifier("...")`의 id는 그냥 문자열이라 오타를 컴파일러가 못 잡음
  - 오늘 `hellCons` 오타 → `NoSuchBeanDefinitionException: No bean named 'hellCons'` → 테스트 실행 전에 실패
